## Implementation findings

The constants define 32 weights per P32 segment, eight segments per 256-weight
tile, and two weights per transition. Thus there are 16 transitions per segment
and 128 per tile. This segmentation must not be confused with a 32-bit numeric
weight datatype, NVFP4's 16-value scale blocks, or a low-rank correction rank.

The logical path is a circular 128-transition history. The window implementation
supports W1 through W3.5 at the reference boundary; individual hardware backends
may accept a narrower range. Each state is 16 bits.

`repack_p32_planar_to_window` reverses physical transition order and packs a
continuous bitstream. `unpack_p32_window_states` extracts each circular 16-bit
window independently. `repack_p32_window_to_planar` restores the canonical
payload. No initial-state or segment-boundary trailer is added, and word count
is unchanged.

Decoding also requires binary bank selectors, an alternate-bank ID and the
codebook version. Extracting the correct state bits while choosing the wrong
bank is not equivalent reconstruction. The segment bank choice does not make
each segment an independently reset trellis.

The decoder audit reports 94 P32 projections with bitwise round-trip and exact
FP32 inner-weight reconstruction, including bank selection. It explicitly
excludes 18 ordinary-QVQ projections. This establishes bounded repack correctness,
not full-model quality or speed.

## Recovery and W4A4 consequences

A lossless window changes where state bits are read, not the quantized weight
values. It cannot by itself improve post-quantization model quality.

Conversion from P32 weights to NVFP4 weights is a separate, potentially lossy
operation. Native A4 inference also introduces activation rounding. Account for
both in the [deployed-output correction target](eora.md#proposed-w4a4-use).
The existence of Hopper/Ampere P32 kernels is not evidence of native NVFP4
tensor-core support.

Bind recovery factors and cached runtime payloads to the correct base weights,
banks, codebook, scale and transform conventions. Correction fitting must use the
same activation coordinate system as inference and explicitly state its precision.
Validate dynamic off/on behavior without mutating the canonical payload.

## Validation to preserve

For repacking changes, check planar/window round-trip, decoded weights, bank and
alternate-bank handling, circular wraparound, all supported rates and payload
bytes. Then separately check full-operator output under the repository's
localized kernel gates.

Report canonical storage, transient repack/cache storage, scales, metadata and
correction bytes separately. Preserve hardware capability gates and fallbacks.
Measure transforms, decode, MMA, reduction and correction as a complete linear
operation; model timings and held-out quality are additional measurements.

Do not infer production promotion from a research function, a successful
synthetic fixture, or one winning shape.
