Preceding device kernel728a9dd8 uses padding[[512,16]]. Device85230490
tests[[512,32]] only; production baselinef41acda8 is unchanged. No production
promotion or full-sweep speedup is claimed.

`d2e28900a1fa8696aff97c702041fe1e674ce042dfa98f1cc40de73763e3d874`.

and output modes, canaries and one/odd ring tests remain unchanged.

## Matched M1024 instruction and SSA audit

All issued counts exactly match728a9dd8: VALU24,580,096;
SALU20,924,416; LDS11,141,120; MFMA22,282,240.
The324 static instructions,106VGPR,26SGPR,no scratch/spills and complete
opcode distribution also match. Compiler LDS grows67,488 to69,440bytes.
An instruction-by-instruction diff changes only layout-related immediates:
slot stride0x4200 becomes0x4400, wave copy offset0x1080 becomes0x1100,
padding shifts and LDS read offsets adjust consistently. MFMA/data types,
wide output stores, slot selection, pointer increments and barriers stay.
Hot vmcnt(8), final vmcnt(0) and absence of copy-routing bpermute/EXEC masks
survive. No new CSE or arithmetic folding is claimed; this isolates physical
address placement while retaining the preceding generated-work reductions.

Candidate metric means, preceding -> wider padding:

| Metric | [[512,16]] | [[512,32]] |
|---|---:|---:|
| LDSBankConflict | 9.97094 | 19.91522 |
| MeanOccupancyPerCU | 6.67008 | 6.66943 |
| SQ_WAIT_INST_LDS | 37,339,184.71 | 53,492,186.61 |

Wider padding is not a bank-conflict improvement. Occupancy is waves/CU;
the conflict metric uses the installed gfx950 formula, not conflicts/access;
LDS issue-wait counts use four-wave-cycle units, not normalized stall percent.
General scheduler eligibility, full stalls, achieved bandwidth and actual
overlap remain unmeasured. Next test the opposite direction,[[512,8]], with
unchanged arithmetic; do not retain32 as an optimization winner.
