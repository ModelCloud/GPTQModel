## Layout/math boundary

New constexpr load-layout bases cover K's five bits and M/N64 or128,
moving the former K32 lane bit into the M/N lane decomposition. The shared
layout preserves vector/lane/wave order and padding[[512,16]]. BK64 uses
its original bases in a separate constexpr branch. The initial reassignment
attempt accidentally materialized basis entries as tensors:208 BK32 tests
failed before execution with get_padded_shared_layout TypeError,16 controls
passed (`/tmp/qvq-bk32-tests.log`). Explicit constexpr declarations fixed it.

All terms remain, but BK32 interleaves high/low every32 K values rather
than64. This is real-arithmetic equivalence with changed floating evaluation,
not a claim of bitwise BK64 equivalence. FP16 operands, FP32 accumulation,
FP16 output and the maximum-absolute0.002 gate remain. Exact controls use
the synchronous kernel at the same BK32 geometry; canonical FP32 checks
are independent. No oracle or threshold was weakened.

224 targeted tests pass after the fix:192 new BK32 cases plus32 ring cases.
Coverage includes tiles64/128, both output/accumulator modes, mixed/full
tails, mask equality, canaries and one/two/three/five K tiles in both prefetch
modes. Added random five-tile tests cover paired-loop remainder behavior for
both BK32 and BK64. After profiling and timing, the complete866-test AMD/
experimental suite passes (14warnings,12.93seconds). Ruff and diff checks pass.

Both new kernels have no scratch/spills; repeated issued counts agree.
The footprint reduction accompanies higher measured occupancy, but multiple
resources and access patterns change, so this is not an isolated causal
proof that LDS alone limited the old kernel. Higher occupancy is not a
performance win by itself. Conflict is the installed gfx950 derived metric,
not conflicts/access; occupancy is waves/CU; LDS wait uses four-wave-cycle
units rather than normalized stalls. General scheduler eligibility, full
stall breakdown, achieved bandwidth and actual overlap remain unmeasured.

## ISA/SSA reduction and costs

The shorter K tile halves per-body MFMA/load work but doubles K iterations;
executed MFMA and LDS totals correctly stay unchanged. Scalar bookkeeping
increases despite the smaller static body. The machine loop advances K
descriptors by64 bytes instead of128. Source constexpr BK selection folds
away; global-to-LDS copies remain vectorized. Hot waits are vmcnt(6),
final vmcnt(0), matching six next-tile copies. No bpermute/EXEC routing
masks or per-loop operand handoff copies appear. Paired iteration constant
slot selection and address reuse survive; both correction terms and shared
X reuse remain. Sixteen wide output stores and32 packed output conversions
stay. Ring barriers are retained. No speculative barrier removal or dropped
correction is used to compensate for extra loop work.
