# Phase 55: H100 W2.5 dual-consumer gate/up

Phase 55 pairs two adjacent N64 output regions in one W2.5 gate/up thread
block. The specialization improves every measured W2.5 full-MLP cell and is
selected only for the physical H100 Llama 3.2 1B gate/up geometry. The
canonical P32 payload and all quantization math remain unchanged.

## Motivation

The grouped Llama gate/up P32 launch previously assigned one N64 output
region to each thread block:

\[
2\ \text{children}\times\frac{8192}{64}=256\ \text{thread blocks}.
\]

Every block independently transferred the same input K stage and initialized
the same PGC level table. W2.5 was the most promising rate for amortizing
that fixed work because its five-bit transition decoder was already using a
four-fragment register-prefetch schedule.

Phase 55 assigns two independent 128-thread WGMMA consumer groups to one
producer:

```text
consumer group 0 -> output columns [n, n + 64)
consumer group 1 -> output columns [n + 64, n + 128)
one 32-thread producer -> shared input TMA transfer
```

The launch becomes:

\[
2\ \text{children}\times\frac{8192}{128}=128\ \text{thread blocks}.
\]

Each block has 288 threads: two 128-thread consumers plus one 32-thread TMA
producer. The consumers share input staging and level-table initialization,
but decode different trellis words and accumulate different output columns.

## Exact kernel mapping

For a child segment \(s\), block coordinate \(b\), and consumer group
\(g\in\{0,1\}\), the original N64 index is

\[
n_{64}=2b+g.
\]

The grouped trellis TMA tile covers eight N16 tiles instead of four:

\[
[4T,\ 8,\ 16,\ 2],
\]

where \(T=5\) transition bits for W2.5 and the final dimension is the two-stage
TMA pipeline. Each consumer addresses its own four-tile slice. Selector bytes
retain the original child and N64 indexing, and each child retains its own
alternative-bank identifier.

The following are unchanged:

- ascending K16 traversal;
- four-fragment decoded-level prefetch order;
- PGC state and selector math;
- WGMMA issue and FP32 accumulation order;
- child output offsets and recovery;
- FP16 rounding boundaries;
- canonical checkpoint and transient grouped payload bytes.

The wider trellis tile raises dynamic shared memory to 54.016 KiB per block.
It does not add persistent VRAM or a new output workspace.

## Promotion gate

The specialization is selected only when all of these conditions hold:

```text
physical CUDA device name == NVIDIA H100
compute capability == 9.0
group category == gate_up
two children
K == 2048
N == 8192 for each child
split count == 1
transition bits == 5 (W2.5)
```

All other rates, devices, shapes, and group plans retain the prior N64
kernel. Production telemetry exposes
`h100_w25_n128_gate_up_launches` so the selected path is observable.

W2 and W3 versions of the same N128 design lost roughly 4--6% in isolated
testing and were not promoted. A follow-up compile-time cleanup ensures those
narrow paths retain their original launch bounds and consumer index
expressions.

## Rejected boundary-fusion experiment

Before the N128 work, an exact recovery-to-SwiGLU/precondition bridge was
implemented and tested. Fifteen cases passed bit-exact and CUDA Graph checks,
but its isolated latency was 26--29 us versus 9.8--11.7 us for the existing
pipeline. Resource inspection showed 84 registers/thread versus 48 in the
existing recovery-high kernel.

The design concentrated all 8192 expensive SiLU evaluations into only 256
threads, forcing 32 serial activations per thread and providing too little
special-function concurrency. It was fully reverted. This result rules out
boundary fusion that collapses activation parallelism merely to remove an
intermediate store.

The closest older W2.5 profiler capture predates later decoder changes, so it

formal exact-SHA full-MLP comparison below is the promotion measurement.

The shared-load conflict count remains high. The measured gain therefore
comes primarily from sharing input TMA work and initialization between two
consumer groups, not from solving the decoder's shared-memory conflicts.

## Correctness and validation

- 136 Hopper P32/grouped-P32 tests pass, including W2.5 and W3 at every
  target M for the real gate/up and QKV shapes.
- 50 grouped-runtime tests pass, including telemetry and fail-closed gates.
- Grouped output equals the plain child schedule exactly and remains bounded
  against the dense P32 oracle.
- Repeated execution and warmed CUDA Graph replay are stable.
- Persistent VRAM, checkpoint bytes, reduction order, and launch count are
  unchanged.
- Compilation used at most four Ninja jobs, one NVCC host thread, and one
  CUDA split-compile partition.

## Next experiment

The N128 block already has two independent consumer warpgroups, so its
optimal decoded-fragment pipeline depth may differ from the N64 kernel. The
next experiment sweeps depths two, three, and four for W2.5 only. It must
preserve each decoded fragment until the corresponding WGMMA operand is no
longer live and must leave N64 code generation untouched.
