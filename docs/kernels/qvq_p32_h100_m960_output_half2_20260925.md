# M960 base-only output Hadamard: specialized normalization and packed scale

The Llama B128/M960 prefill graph uses the base-only P32 output Hadamard at
N2048 and N8192 while Rank-8 prefill is disabled. The register-high kernel
previously kept `normalize_first` as a runtime branch and converted each FP16
result to FP32 for the final scale multiply. This change compiles separate
normalization variants and uses one native `half2` scale multiply when the
input was already normalized. The non-normalized variant retains the original
FP32 reciprocal and rounding sequence. The ABI and dispatch shape are
unchanged; no persistent weight or activation cache is added.

The runtime branch was the decisive issue. An initial packed division plus
packed scale experiment made N8192 slower. Packed scale alone with the runtime
branch raised N8192 register use from 32 to 40 per thread and was also slower.
Making normalization a compile-time parameter returned the N8192 normalized
kernel to 32 registers/thread, zero local spill bytes, and preserved 25
registers/thread for N2048.

## Exact arithmetic gates

- On SM90, native FP16 multiplication matched FP32 multiplication rounded to
  FP16 for every finite FP16 input paired with six scales, including
  subnormal, unit, and maximal finite scales: zero mismatches.
- The direct M960 ABI comparison had zero output-bit differences against the
  pinned control at N2048 and N8192, with normalization both off and on.
- Warm normalized microbenchmark: N2048 6.812 to 6.457 µs (1.055x); N8192
  20.155 to 19.182 µs (1.051x). The non-normalized variant remained exact.
- Two full B128/M960 GSM8K-Platinum pairs produced 1,209/1,209 identical
  generated token streams, 543 correct, and zero invalid in every arm. Each
  pair checked dataset index, rendered prompt, and input IDs before output
  IDs. Model, data order, FA2, CPU affinity, XLA cache, server source, and
  runner executable bytes were held fixed; only the QVQ library changed.

Matched mean padded and useful prefill improved 1.024%; wall time fell
0.669%. Decode code is unchanged, so the small decode timing variation is
not a claimed decode optimization. The reported rates include padded and
useful tokens separately; the per-stream rate divides padded aggregate
decode by 128.

The raw per-run JSON and logs are under
`/var/tmp/b128-output-half2-{control-a,candidate-a,control-b,candidate-b}-*`
on the H100 test machine. The model is the QVQ Llama 3.2 1B Seed-7 snapshot;
the dataset is all 1,209 GSM8K-Platinum rows. The benchmark used 128 serving
lanes, prefill bucket 960, FA2, an 8,192-token logical context, 736 physical
KV pages, GPU-local CPU cores, Rank-8 off in prefill and on in decode, and
eight projector warps.
